# OpenClash 断网保护（Kill-Switch）说明

> 目标：给指定设备/网段做「**要么走代理，要么断网**」的 fail-closed 保护。
> 当 OpenClash **重启 / 崩溃 / 关闭**时，这些设备**立刻断网**，而**不会回落到国内网络直连**——从而杜绝真实 IP 泄漏。
> 适用场景：跨境电商养号机、需要严格防泄漏防关联的运营环境。

---

## 一、核心原理：两条路，只在「直连路」上砌墙

设备流量出门有**两条完全不同的路**：

- **代理路**：被 OpenClash 半路截走 → 进代理节点 → 出国。
- **直连路**：没人截 → 直接从路由器 WAN 口出去（国内网络）。

Kill-Switch = 在**「直连路」上砌一道墙（防火墙 DROP）**。
OpenClash 平时把流量提前引上「代理路」，**绕开这道墙**。

> **OpenClash 在 = 走代理路绕过墙；OpenClash 没了 = 只能走直连路，一头撞墙 = 断网。**

---

## 二、图解：数据包在路由器里的走向

### ✅ OpenClash 运行时
```
设备 ──▶ 路由器
          │
          ├─[PREROUTING 第一关]  OpenClash 在这里把包截走
          │        │
          │        ▼
          │   Clash 核心 ──▶ 代理节点 ──▶ 🌍 (指定出口)
          │
          └─(FORWARD 那道墙? 没走到，被前面截走了)   ✅ 正常上网
```

### ⛔ OpenClash 关闭 / 重启的瞬间
```
设备 ──▶ 路由器
          │
          ├─[PREROUTING 第一关]  OpenClash 没了，没人截 → 放行
          │        │
          │        ▼
          ├─[FORWARD 这道墙 🧱]  你的 DROP 规则在这
          │        │
          │        ▼
          │      ✋ 丢弃 (DROP)   ⛔ 断网，出不去
          │
          └─(本来会从 WAN 直连国内 → 被墙挡下，绝不回落)
```

---

## 三、为什么「不会回落国内」

关键在墙的**位置**：它砌在 **FORWARD 链**（设备 → WAN 的必经之路）。

- OpenClash 在：包在**更早的 PREROUTING** 就被引走，到不了 FORWARD，墙对它无效；
- OpenClash 没了：包往下走，一定经过 FORWARD → **撞墙丢弃**。

而「回落国内」恰恰就是「包从 FORWARD 出 WAN」这件事——墙正好挡在这一步，**回落这条路被物理封死**。

---

## 四、为什么 OpenClash 停了、墙还在？

因为这道墙写在**路由器自己的防火墙**（`/etc/config/firewall`）里，**开机常驻**，和 OpenClash 是两套东西。
OpenClash 启停只增删**它自己**的规则（PREROUTING 那些），动不了你这道墙。

| 状态 | PREROUTING 截流（OpenClash 管） | FORWARD 那道墙（你管） | 结果 |
|------|:---:|:---:|:---:|
| OpenClash 运行 | 有 ✅ | 一直在 | 走代理 ✅ |
| OpenClash 停/重启 | 没了 ❌ | **一直在** 🧱 | 断网 ⛔ |

> 墙「永远在」，OpenClash 的截流「时有时无」，两者组合即成 Kill-Switch。
> ⚠️ **千万别把这条规则写进 OpenClash 的自定义规则里**——那样 OpenClash 停止时会把它一起清掉，保护失效。

---

## 五、操作步骤

### 方式 A：LuCI 图形界面（推荐，方便查看增删）
`网络 → 防火墙 → 通信规则 (Traffic Rules) → 添加`

| 字段 | 填写 |
|------|------|
| 名称 | `KillSwitch-养号机`（带前缀，方便识别） |
| 协议 | 任意 |
| 源区域 | **lan** |
| 源地址 | `10.0.100.0/24`（要保护的设备/网段） |
| 目标区域 | **wan** |
| 动作 | **拒绝(reject)** 或 **丢弃(drop)** |

保存并应用即可。每台设备/每个网段一条，列表里一目了然。

### 方式 B：命令行（nftables / 新版 OpenWrt）
```sh
# WAN 接口名按实际改：pppoe-wan / eth1 / wan
nft add rule inet fw4 forward ip saddr 10.0.100.0/24 oifname "pppoe-wan" drop
```
> 需写入持久化配置，否则重启丢失。图形界面方式 A 会自动持久化，推荐。

---

## 六、方便查看 / 管理

- **图形界面**：所有 Kill-Switch 规则都在 `防火墙 → 通信规则` 列表里，命名统一带 `KillSwitch-` 前缀，一眼认出。
- **临时放行某设备**：把对应规则的「启用」取消勾选即可，无需删除。
- **命令行查看当前生效的墙**：
  ```sh
  nft list chain inet fw4 forward | grep drop
  ```

---

## 七、验证（照着测，眼见为实）

1. 目标设备**能正常上外网**（OpenClash 运行中）；
2. **手动停掉 OpenClash** → 设备**立刻打不开网页**（证明没回落国内）✅；
3. **重启 OpenClash** → 设备恢复上网。

三步都对 = 「要么走代理，要么断网，绝不直连泄漏」生效。

---

## 八、配合分流规则使用

在 OpenClash 配置里给养号网段指定出口（源 IP 分流）：
```yaml
- SRC-IP-CIDR,10.0.100.0/24,us01最终选择   # 该网段固定走美国落地 IP（防关联）
```
再叠加本文的 Kill-Switch 防火墙规则：

- OpenClash 在 → 养号网段固定走美国落地 IP；
- OpenClash 挂 → 养号网段**直接断网**，绝不漏到国内。

**最终效果：走美国代理 或 断网，没有第三种可能。**

---

## 九、注意事项

- 只对**填进源地址的设备/网段**生效；其它设备 OpenClash 停了仍会直连，需保护就一并加入。
- 断网时该设备与**路由器/局域网**仍连通（只是出不了外网），不影响你重启 OpenClash 或管理路由。
- `SRC-IP-CIDR` 是「源 IP（设备）」，`IP-CIDR` 是「目标 IP」，按设备分流务必用 `SRC-IP-CIDR`。
