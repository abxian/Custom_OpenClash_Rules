# OpenClash 断网保护（Kill-Switch）完整说明

> 目标：给指定设备/网段做「**要么走代理，要么断网**」的 fail-closed 保护。
> 当 OpenClash **重启 / 崩溃 / 关闭**时，这些设备**立刻断网**，而**不会回落到国内网络直连**，杜绝真实 IP 泄漏。
> 适用：跨境电商养号机、需严格防泄漏防关联的运营环境。

---

## 〇、核心心法（记住这个就不会配错）

> **Kill-Switch =「源：设备在哪个网络」→「目标：所有能出网的口」→ 丢弃。**
> - 换上网方式（网线 / WiFi）→ 只影响「**目标**是哪个出口」；
> - 换设备位置（主网 / 访客网）→ 只影响「**源**是哪个网络」；
> - 原理完全一样，跟网线还是 WiFi 无关。

---

## 一、核心原理：两条路，只在「直连路」上砌墙

设备流量出门有**两条完全不同的路**：
- **代理路**：被 OpenClash 半路截走 → 进代理节点 → 出国。
- **直连路**：没人截 → 直接从路由器出口（WAN）出去（国内网络）。

Kill-Switch = 在**「直连路」上砌一道墙（防火墙 DROP）**。
OpenClash 平时把流量提前引上「代理路」，**绕开这道墙**。

> **OpenClash 在 = 走代理路绕过墙；OpenClash 没了 = 只能走直连路，撞墙 = 断网。**

---

## 二、图解：数据包在路由器里的走向

### ✅ OpenClash 运行时
```
设备 ──▶ 路由器
          │
          ├─[PREROUTING 第一关]  OpenClash 在这里把包截走
          │        │
          │        ▼
          │   Clash 核心 ──▶ 代理节点 ──▶ 🌍 (指定出口)
          │
          └─(FORWARD 那道墙? 没走到，被前面截走了)   ✅ 正常上网
```

### ⛔ OpenClash 关闭 / 重启的瞬间
```
设备 ──▶ 路由器
          │
          ├─[PREROUTING 第一关]  OpenClash 没了，没人截 → 放行
          │        │
          │        ▼
          ├─[FORWARD 这道墙 🧱]  你的 DROP 规则在这
          │        │
          │        ▼
          │      ✋ 丢弃 (DROP)   ⛔ 断网，出不去
          │
          └─(本来会从出口直连国内 → 被墙挡下，绝不回落)
```

---

## 三、为什么「不会回落国内」

墙砌在 **FORWARD 链**（设备 → 出口的必经之路）：
- OpenClash 在：包在**更早的 PREROUTING** 就被引走，到不了 FORWARD，墙对它无效；
- OpenClash 没了：包往下走，一定经过 FORWARD → **撞墙丢弃**。

而「回落国内」就是「包从 FORWARD 出 WAN」——墙正好挡在这一步，**回落这条路被物理封死**。

---

## 四、为什么 OpenClash 停了、墙还在？

这道墙写在**路由器自己的防火墙**（`/etc/config/firewall`）里，**开机常驻**，和 OpenClash 是两套东西。OpenClash 启停只增删**它自己**的规则（PREROUTING 那些），动不了你这道墙。

| 状态 | PREROUTING 截流（OpenClash 管） | FORWARD 那道墙（你管） | 结果 |
|------|:---:|:---:|:---:|
| OpenClash 运行 | 有 ✅ | 一直在 | 走代理 ✅ |
| OpenClash 停/重启 | 没了 ❌ | **一直在** 🧱 | 断网 ⛔ |

> ⚠️ **千万别把这条规则写进 OpenClash 的自定义规则里**——那样 OpenClash 停止时会把它一起清掉，保护失效。要放在 LuCI「防火墙 → 通信规则」里（持久化）。

---

## 五、防火墙「通信规则」每个选项详解

规则本质：先**匹配**哪些流量（条件），再**处理**（放行/丢弃/拒绝）。

### 5.1 常规设置

#### 名称
规则备注名，给你自己看。建议带前缀 `KillSwitch-养号机` 方便识别。

#### 协议
匹配哪种协议：
| 选项 | 含义 | 用途 |
|------|------|------|
| TCP | 网页、大部分 App | 只想管网页/下载 |
| UDP | DNS、游戏、QUIC、语音视频 | 只想管 UDP |
| TCP+UDP | 两者 | 最常用组合 |
| ICMP | ping | 只想禁/放 ping |
| **任意** | **所有协议** | **断网/kill-switch 用这个**（断得彻底） |
| 自定义 | 指定协议号 | 特殊需求 |

#### 源区域（从哪来）
流量的**入口区域**：`lan`（内网）/`wan`（外网）/`guest`（访客）/自定义。
> kill-switch：源区域 = **设备所在区域**（主网=lan，访客网=guest）。

#### 源地址（哪些设备）
精确到 **IP / 网段**，如 `10.0.100.0/24`。留空 = 该源区域所有设备。
> kill-switch：填养号网段，精准锁定。

#### 源端口
按**发起方端口**过滤。客户端端口随机，一般**留空**。

#### 目标区域（要去哪）
流量的**出口区域**：`wan/wan6`（物理外网）/自定义出口。
> kill-switch：目标区域 = **所有能出网的口**（wan+wan6+所有自定义出口）。

#### 目标地址（访问哪些目标）
精确到**对方 IP/网段**。留空 = 所有目标。
> kill-switch：留空（要全断）。

#### 目标端口
按**对方端口**过滤：`443`=HTTPS、`80`=HTTP、`53`=DNS、`22`=SSH。
> 例：只禁网页 → 填 `80,443`；kill-switch 要全断 → **留空**。

#### 操作（匹配后怎么处理）⭐
| 动作 | 效果 | 场景 |
|------|------|------|
| **接受(accept)** | 放行 | 允许某流量 |
| **丢弃(drop)** | **静默丢包**，对方一直转圈超时，无反馈 | **kill-switch 推荐**（隐蔽） |
| **拒绝(reject)** | 立即返回"拒绝"，对方秒报错 | 想"立刻明确断" |
| 无操作(notrack) | 不追踪连接（性能优化） | 高并发，极少用 |

> drop vs reject 都能断网；防泄漏选 **drop**（更隐蔽，不给探测反馈）。

### 5.2 高级设置（一般不用填）

#### 匹配设备
按**接口名**（`eth0`/`pppoe-wan`/`wwan`）匹配进出设备，比"区域"更底层。一般用区域就够，不用填。

#### 地址族限制 ⭐（唯一需要确认的项）
| 选项 | 含义 |
|------|------|
| **IPv4 和 IPv6** | 两者都匹配 —— **kill-switch 选这个**，IPv6 也断，防漏 |
| 仅 IPv4 | 只管 IPv4（IPv6 会漏！） |
| 仅 IPv6 | 只管 IPv6 |

#### 使用 ip 集（ipset）
引用一个 nftables 集合（一批预定义 IP）。要匹配一大批 IP 时用，普通场景不用。

#### 源 MAC 地址 ⭐（WiFi 场景强烈建议）
按设备**物理地址(MAC)**匹配。WiFi 设备 IP 常变（DHCP），但 **MAC 不变**。用 MAC 锁定，设备换 IP、换网段都照样被管住，比 IP 更牢。

#### 匹配助手（conntrack helper）
匹配用特定连接跟踪助手的流量（FTP/SIP 等）。特殊协议才用，留"任意"。

#### 匹配标记（fwmark）
匹配带特定防火墙标记的包，配合策略路由/mangle。进阶，不用填。

#### 匹配 DSCP
匹配带 QoS 优先级标记的流量。做 QoS 才用，不用填。

#### 限制匹配（rate limit）
限制规则每秒匹配多少包（防洪水/限流）。
> kill-switch 要**全断**，选"**无限制**"，别限速（否则漏包）。

### 5.3 时间限制（让规则按时间生效）
| 选项 | 用途 |
|------|------|
| 一周中的日期 | 只在周几生效 |
| 一天中的时间 | 只在某时段生效（如 09:00–18:00） |
| 起止日期 | 只在某段日期生效 |
| 时区(UTC/本地) | 时间按哪个时区算 |

> kill-switch **全部留空**（24 小时永久生效）。时间限制适合"家长控制"（定时断网）。

## 六、不同上网方式 / 网络场景

**底层模型**：OpenWrt 防火墙只认「区域(zone)」，每个接口归一个区域，流量总是"源区域 → 目标区域"。**跟物理是网线还是 WiFi 无关**。所以换环境只需改对应的区域。

### 6.1 路由器靠 WiFi 上网（没插网线）✅ 能用
路由靠 WiFi 连上游（无线中继 / WISP）时，那个"连上游 WiFi 的接口"（OpenWrt 通常叫 **`wwan`**）**就是你的 WAN 出口**，一般已归在 `wan` 区域。
- kill-switch 照常用：**目标区域选"包含 wwan 的那个区域"**（多数就是 `wan`）。
- 确认方法：`网络 → 接口` 看上游 WiFi 是哪个接口、协议是否 DHCP客户端；`网络 → 防火墙` 看它在哪个区域。

### 6.2 又有 WiFi 中继、又插了网线（多出口）⚠️ 必须都堵
两条上网路 = 两个出口。只堵一个，OpenClash 停了设备会**从另一个溜出去**。
- **目标区域要把所有出口区域全选上**：`wan + wan6 + wwan所在区域 + 自定义出口(foshan/pdd 等)`。
- 判断有几个出口：`网络 → 接口` 里凡是"能连外网、有默认路由"的接口都是出口，都要堵。

### 6.3 访客网络（guest）✅ 一样设置，只改"源"
访客网通常是独立接口和区域（`guest`），有自己的网段（如 `192.168.3.0/24`）。
| 项 | 主网设备 | 访客网设备 |
|----|---------|-----------|
| 源区域 | lan | **guest** |
| 源地址 | 10.0.100.0/24 | **访客网段**（如 192.168.3.0/24） |
| 目标区域 | 所有出口 | 所有出口（不变） |
| 操作 | 丢弃 | 丢弃（不变） |
> 若访客网和 lan 是同一区域（没单独分），则不用改，`lan` 已涵盖。

### 6.4 用 MAC 锁设备（WiFi 环境强烈建议）
WiFi 设备 IP 常变，用 IP 锁可能失效。**高级设置 → 源 MAC 地址** 填养号机 MAC（不变），设备换 IP/网段都照样被 kill-switch 管住。可代替或叠加源地址用。

### 6.5 一张表看懂"改什么"
| 你的变化 | 只需调整 |
|---------|---------|
| 网线上网 ↔ WiFi中继上网 | **目标区域**（对准出口） |
| 单出口 → 多出口 | **目标区域**（所有出口都加上） |
| 设备在主网 → 在访客网 | **源区域 + 源地址** |
| 设备 IP 会变(DHCP) | 用**源 MAC 地址**锁死 |

## 七、操作步骤（LuCI 图形界面）

`网络 → 防火墙 → 通信规则(Traffic Rules) → 添加`

**标准 kill-switch 填法：**
| 项 | 值 |
|----|-----|
| 名称 | `KillSwitch-养号机` |
| 协议 | 任意 |
| 源区域 | lan（访客网则填 guest） |
| 源地址 | `10.0.100.0/24`（或用**源MAC**锁得更死） |
| 源端口 | 留空 |
| 目标区域 | **所有出口**：wan + wan6 +（wwan区域 / foshan / pdd 等） |
| 目标地址 | 留空 |
| 目标端口 | 留空 |
| 操作 | **丢弃(drop)** |
| 地址族限制（高级） | **IPv4 和 IPv6** |
| 其余高级/时间限制 | 全默认/留空 |

保存并应用。

**命令行版（nftables，接口名按实际改）：**
```sh
nft add rule inet fw4 forward ip saddr 10.0.100.0/24 oifname { "pppoe-wan","wwan" } drop
```

## 八、方便查看 / 管理
- 所有规则都在 `防火墙 → 通信规则` 列表，命名统一带 `KillSwitch-` 前缀，一眼认出。
- 临时放行某设备：把对应规则「启用」取消勾选即可，无需删除。
- 命令行查看当前生效的墙：`nft list chain inet fw4 forward | grep drop`

## 九、验证（照着测，眼见为实）
1. 目标设备**能正常上外网**（OpenClash 运行中）；
2. **手动停掉 OpenClash → 设备立刻断网**（打不开任何网页）✅；
3. **重启 OpenClash → 设备恢复**。

第 2 步若还能上网 = 有出口没堵 → 回 `网络→接口` 找漏掉的出口，加进目标区域。

## 十、配合分流规则使用
OpenClash 配置里给养号网段指定出口：
```yaml
- SRC-IP-CIDR,10.0.100.0/24,us01最终选择   # 该网段固定走美国落地 IP（防关联）
```
叠加本文 kill-switch：
- OpenClash 在 → 养号网段固定走美国落地 IP；
- OpenClash 挂 → 养号网段**直接断网**，绝不漏到国内。

**最终效果：走美国代理 或 断网，没有第三种可能。**

## 十一、能否"万无一失"？（4 个前提）
| # | 条件 | 说明 |
|---|------|------|
| 1 | **所有出网口都堵** | 网线WAN + WiFi中继 + 自定义出口，全加进目标区域 |
| 2 | **IPv6 也堵** | 地址族限制 = IPv4 和 IPv6 |
| 3 | **规则排在放行规则前** | 新建通信规则一般在前，通常没问题 |
| 4 | **设备没有别的上网途径** | 养号机不能自己插 4G / 连别的 WiFi 绕过路由器（物理层，防火墙管不了） |

满足这 4 点 = 对这台路由器而言万无一失。

---

## 十二、注意事项
- 只对**填进源地址/源MAC 的设备**生效；其它设备 OpenClash 停了仍会直连，要保护就一并加入。
- 断网时该设备与**路由器/局域网**仍连通（只出不了外网），不影响你重启 OpenClash 或管理路由。
- `SRC-IP-CIDR` 是"源 IP（设备）"，`IP-CIDR` 是"目标 IP"，按设备分流务必用 `SRC-IP-CIDR`。
- kill-switch 规则务必放在 LuCI 防火墙里（持久化），**不要**写进 OpenClash 自定义规则。
